# 実モデル評価用APIの残高不足

2026-11-10、隔離ローカルWorkerでの受入47ターン再評価の後半から、OpenAI上流HTTP 429が連続した。アプリの公開HTTPステータスは503であり、上流の429と区別する。本番キーとの同一性・本番サービスへの影響は未確認。

全体評価は `data/logs/qa-acceptance-all-1794276026223.json` に29 Pass / 18 Fail / 未実行0として保存。HTTP 500は0、HTTP 503は13。うち8ターンは上流429、2ターンは意味解析、3ターンは検索契約の実行失敗で、残りの失敗を残高不足だけの問題と扱わない。この直前の対象11ターンは全件Passだったが、全47ターンの合格には代用しない。

原因を区別するため、設定済みの評価用キーで最小の1リクエストのみ確認した。結果はHTTP 429、`error.type=insufficient_quota`、`error.code=credit_balance_exhausted`。記録は `data/logs/redesign-20261102/openai-429-diagnostic-20261110.json`。秘密値・リクエストのAuthorization・上流の自由文エラー本文は保存しない。

[OpenAI公式エラーガイド](https://developers.openai.com/api/docs/guides/error-codes)では、このcodeは組織の前払い残高不足を示し、復旧には残高の補充が必要とされる。再試行で復旧するエラーとは扱わない。

実モデルを使う追加呼び出しと全体評価の再実行を停止した。所有者へ、残高補充または利用可能な既存キーの環境設定を依頼済み。キーをチャットへ貼るようには依頼しない。未使用の別キーの有無、支払管理画面、残高額は確認できていない。自動購入・課金契約変更は行っていない。

実装・原本の解析・読み取り専用native照合・単体試験は継続可能。次に、クレジット不足を安全な型付きエラーとして記録し、評価runnerが `--continue-on-failure` でも同じ状態で呼び出しを続けないよう修正する。復旧後は最小リクエストで利用可能性を確認してから、未完の実モデル評価を再開する。Blockedや未実行をPassへ含めず、正式QAのAやリリース判定を更新しない。
